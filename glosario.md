# Glosario bilingüe

Términos tal como aparecen a lo largo de los capítulos de esta guía. El término en inglés es el usado por el libro original; la definición es síntesis propia.

| Término (inglés) | Español | Definición breve |
|---|---|---|
| Incident | Incidente | Evento adverso en un sistema o red, o la amenaza de que ocurra, que implica daño o intento de daño. |
| Event | Evento | Cualquier ocurrencia observable en un sistema o red. |
| Event of Interest (EOI) | Evento de interés | Evento que amerita investigación según criterios organizacionales de significancia. |
| Indicator of Compromise (IOC) | Indicador de compromiso | Artefacto técnico o de comportamiento que sugiere actividad maliciosa. |
| TTP (Tactics, Techniques, Procedures) | Tácticas, técnicas y procedimientos | Marco para catalogar el comportamiento de un atacante. |
| Mean Time To Detect (MTTD) | Tiempo medio de detección | Métrica de velocidad de detección. |
| Mean Time To Respond (MTTR) | Tiempo medio de respuesta | Métrica de velocidad de respuesta. |
| Waypoint | Punto de decisión / hito | Unidad conceptual de DAIR — no un "paso" con inicio y fin discreto. |
| Outcome | Resultado esperado | El resultado deseado asociado a cada waypoint. |
| Action | Acción (recurrente/continua) | Actividad que se sostiene en el tiempo, no un evento puntual. |
| Decision Maker | Decision-maker / tomador de decisión | Persona con autoridad para asignar recursos de respuesta (gerencia, legales, dueño de negocio). |
| Scope (actividad) | Scoping / determinación de alcance | Determinar la amplitud real de un compromiso. |
| Containment | Contención | Frenar la actividad del atacante preservando evidencia. |
| Eradication | Erradicación | Remover la presencia del atacante y los mecanismos de persistencia. |
| Recovery | Recuperación | Restaurar sistemas a estado operativo validado. |
| Debrief | Debrief / cierre y aprendizaje | Cierre formal del incidente y captura de lecciones aprendidas. |
| After-Action Review (AAR) | Revisión posterior a la acción | Reflexión estructurada post-incidente. |
| Root Cause Analysis (RCA) | Análisis de causa raíz | Identificación de las condiciones de fondo que permitieron el compromiso. |
| Persistence mechanism | Mecanismo de persistencia | Técnica usada por el atacante para mantener acceso a largo plazo. |
| Lateral movement | Movimiento lateral | Desplazamiento del atacante entre sistemas dentro de la red comprometida. |
| Threat hunting | Caza de amenazas / hunting | Búsqueda proactiva de EOIs sin partir de una alerta. |
| Pyramid of Pain | Pirámide del dolor | Marco que ordena artefactos del adversario según el costo de cambiarlos. |
| Signature-based detection | Detección basada en firmas | Coincidencia de patrones conocidos (hashes, dominios, etc.). |
| Behavioral detection | Detección basada en comportamiento | Detección por desvío de una línea base de actividad normal. |
| Human-in-the-loop (HITL) | Humano en el circuito | Revisión humana obligatoria sobre la salida de un modelo de ML. |
| Shared Responsibility Model | Modelo de responsabilidad compartida | División de responsabilidades de seguridad entre proveedor cloud y cliente. |
| Management plane | Plano de gestión | Capa de control en cloud (identidad, accesos). |
| Data plane | Plano de datos | Capa de acceso a aplicación y almacenamiento en cloud. |
| Ephemeral resource | Recurso efímero | Recurso cloud de vida corta, difícil de preservar forense. |
| Human-Operated Ransomware (HumOR) | Ransomware operado por humanos | Ransomware con reconocimiento y movimiento lateral manual antes del cifrado. |
| Ransomware-as-a-Service (RaaS) | Ransomware como servicio | Modelo de reparto de ingresos entre operador de la plataforma y afiliados. |
| Initial Access Broker (IAB) | Bróker de acceso inicial | Actor que vende acceso ya comprometido a otros atacantes. |
| Operational Technology (OT) | Tecnología operacional | Sistemas que controlan procesos físicos (ICS, SCADA, DCS, PLC). |
| Purdue Model | Modelo Purdue | Arquitectura jerárquica de red que separa IT empresarial de control industrial. |
| Safety (en contexto OT) | Seguridad física / seguridad de las personas | Prioridad por sobre la confidencialidad de datos en entornos OT. |
| Break-glass account | Cuenta de emergencia / break-glass | Credencial sellada para acceso de emergencia cuando fallan otros mecanismos. |
| Just-in-time elevation | Elevación just-in-time | Activación de rol de acceso elevado acotada en el tiempo. |
| PICERL | PICERL | Preparation-Identification-Containment-Eradication-Recovery-Lessons Learned; modelo lineal clásico (Schultz, 1990). |
| DAIR | DAIR | Dynamic Approach to Incident Response — el modelo central del libro. |
